# Spotify Next-Track Recommender System

A production-grade MLOps pipeline for a song recommender system built with:

| Layer | Technology |
|---|---|
| ML Model | PyTorch Two-Tower Neural Network |
| Model Serving | FastAPI + Uvicorn |
| Feature Cache | Redis |
| Experiment Tracking | MLflow |
| Monitoring | Prometheus |
| Drift Detection | KL Divergence (GMM-based) |
| Containerization | Docker Compose |

---

## Architecture

```
┌──────────────────────────────────────────────────────────────┐
│                     OFFLINE TRAINING                         │
│  Spotify MPD ──► Preprocessing ──► Two-Tower PyTorch Model  │
│                         │                   │                │
│                  track_embeddings.npy    MLflow Run          │
│                  training_dist.pkl                           │
└──────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌──────────────────────────────────────────────────────────────┐
│                   ONLINE SERVING (Docker)                    │
│                                                              │
│  POST /recommend                                             │
│       │                                                      │
│       ├─► Redis Cache ◄──────────────┐                      │
│       │    (HIT → return cached)     │ (MISS → store)       │
│       │                              │                       │
│       ├─► Playlist Tower ────────────┘                       │
│       │                                                      │
│       ├─► FAISS HNSW ANN search over track_embeddings.npy  │
│       │                                                      │
│       ├─► Drift Detector (KL divergence every 100 requests) │
│       │                                                      │
│       └─► Prometheus /metrics                               │
└──────────────────────────────────────────────────────────────┘
```

## Prerequisites

- **Docker Desktop** (v24+) with Docker Compose V2
- **Python 3.11+** (for local training only)
- (Optional) NVIDIA GPU with CUDA for faster training

## Step 1 — Get the Data

### Option A: Spotify Million Playlist Dataset (recommended for submission)

1. Register at [https://www.aicrowd.com/challenges/spotify-million-playlist-dataset-challenge](https://www.aicrowd.com/challenges/spotify-million-playlist-dataset-challenge)
2. Download and unzip the dataset
3. Place the JSON files inside `data/`:

```
data/
  mpd.slice.0-999.json
  mpd.slice.1000-1999.json
  ...
```

The training pipeline streams playlists from the JSON files and generates training triples lazily, while using only the first `MAX_PLAYLISTS` playlists (default: 1000) for fast iteration.

### Option B: Synthetic Data (for demo / testing)

No action needed — if `data/` is empty, synthetic data is auto-generated.

---

## Step 2 — Train the Model (locally)

Start an MLflow server first (or let Docker Compose handle it — see Step 3):

```bash
# Install dependencies
pip install -r requirements.txt

# (Optional) Start a local MLflow server
mlflow server --backend-store-uri sqlite:///mlflow.db \
              --default-artifact-root ./mlflow_artifacts \
              --host 0.0.0.0 --port 5001 &

export MLFLOW_TRACKING_URI=http://localhost:5001
# Optional: choose a reproducible training seed
export SEED=42

# Run training
bash scripts/run_training.sh
```

Or with custom settings:

```bash
MAX_PLAYLISTS=5000 NUM_EPOCHS=20 EMBEDDING_DIM=128 \
    bash scripts/run_training.sh
```

After training you will have:
- `artifacts/track_embeddings.npy` — all track vectors
- `artifacts/training_track_distribution.pkl` — GMM baseline for drift
- `artifacts/mlflow_run_id.txt` — run ID for the API to load from
- `submission.json` — auto-generated with a valid test playlist ID

---

## Step 3 — Launch All Services

```bash
docker-compose up -d --build
```

This starts:
| Container | Port | What |
|---|---|---|
| `recommender-api` | 8000 | FastAPI recommender |
| `recommender-redis` | 6379 | Redis feature cache |
http://localhost:5001

Wait ~30 seconds for MLflow to initialize, then check:

```bash
docker-compose ps          # all should show "healthy"
docker-compose logs api    # watch startup logs
```

---

## Step 4 — Run Training Inside Docker (Alternative)

If you prefer to train inside the Docker environment:

```bash
# Start infrastructure first
docker-compose up -d redis mlflow

# Wait for MLflow to be healthy, then run training
docker-compose run --rm \
  -e MLFLOW_TRACKING_URI=http://mlflow:5000 \
  -e DATA_DIR=/app/data \
  -e ARTIFACTS_DIR=/app/artifacts \
  -v $(pwd)/data:/app/data \
  -v $(pwd)/artifacts:/app/artifacts \
  api python src/training/train.py

# Now bring up the API
docker-compose up -d api
```

## Using the API

### Health Check

```bash
curl http://localhost:8000/health
# {"status":"ok"}
```

### Get Recommendations

```bash
# Get the test playlist ID from submission.json
TEST_PID=$(python3 -c "import json; print(json.load(open('submission.json'))['test_playlist_id'])")

curl -X POST http://localhost:8000/recommend \
     -H "Content-Type: application/json" \
     -d "{\"playlist_id\": $TEST_PID, \"top_k\": 10}"
```

**Response:**
```json
{
  "recommended_track_ids": [42, 1337, 7, 99, 512, 3, 27, 888, 102, 44],
  "retrieved_from_cache": false
}
```

**Second call** (same playlist_id) will return `"retrieved_from_cache": true`.

### Test 404 Error

```bash
curl -X POST http://localhost:8000/recommend \
     -H "Content-Type: application/json" \
     -d '{"playlist_id": -1, "top_k": 5}'
# {"detail":"Playlist not found"}
```

### Prometheus Metrics

```bash
curl http://localhost:8000/metrics
```

Key metrics exposed:
| Metric | Type | Description |
|---|---|---|
| `recommendation_latency_seconds` | Histogram | Request latency |
| `user_embedding_cache_hits_total` | Counter | Redis cache hits |
| `user_embedding_cache_misses_total` | Counter | Redis cache misses |
| `concept_drift_kl_divergence` | Gauge | Latest KL divergence value |

## Monitoring

### MLflow UI

Open [http://localhost:5001](http://localhost:5001) to browse:
- Experiment runs with logged parameters and metrics
- Training loss/accuracy curves per epoch
- Registered model artifacts

### Concept Drift Simulation

```bash
# Simulate 150 requests to trigger drift detection
python scripts/simulate_drift.py \
    --api-url http://localhost:8000 \
    --artifacts-dir artifacts \
    --count 150

# Watch for the DRIFT DETECTED log
docker-compose logs -f api | grep "DRIFT"
```

The drift detector fires every `DRIFT_WINDOW` requests (default: 100). When KL divergence exceeds `DRIFT_KL_THRESHOLD` (default: 0.5), it logs:
```
WARNING  recommender:main.py:  DRIFT DETECTED: KL divergence=X.XXXX exceeds threshold=0.5
```

## Configuration

All settings are controlled via environment variables (set in `docker-compose.yml` or your shell):

| Variable | Default | Description |
|---|---|---|
| `MLFLOW_TRACKING_URI` | required for training; `http://mlflow:5000` in Docker Compose | MLflow server URL |
| `REDIS_HOST` | `redis` | Redis hostname |
| `REDIS_PORT` | `6379` | Redis port |
| `EMBEDDING_CACHE_TTL_SECONDS` | `3600` | Cache TTL (seconds) |
| `DRIFT_KL_THRESHOLD` | `0.5` | KL divergence alert threshold |
| `DRIFT_WINDOW` | `100` | Requests before drift check |
| `ARTIFACTS_DIR` | `/app/artifacts` | Artifact directory |
| `MAX_PLAYLISTS` | `1000` | Training data size |
| `EMBEDDING_DIM` | `64` | Embedding size |
| `OUTPUT_DIM` | `64` | Tower output dimension |
| `NUM_EPOCHS` | `10` | Training epochs |
| `LEARNING_RATE` | `1e-3` | Adam learning rate |
| `BATCH_SIZE` | `256` | Training batch size |
| `SEED` | `42` | Random seed for reproducible training |

## Troubleshooting

**API can't connect to Redis/MLflow:**
> Inside Docker, services talk by service name. Check that `REDIS_HOST=redis` and `MLFLOW_TRACKING_URI=http://mlflow:5000` are set.

**`artifacts/` directory is empty after docker-compose up:**
> You must run training before starting the API. See Step 2 or Step 4.

**MLflow takes too long to start:**
> The MLflow service installs Python packages on first start. Wait ~60s or run `docker-compose logs mlflow` to track progress.

**Out of memory on small machines:**
> Reduce `MAX_PLAYLISTS=200` and `BATCH_SIZE=64` in your training command.
